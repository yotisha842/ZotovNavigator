## Слайд 5 — Решение

### Что на слайде
```
Зотов.Навигатор — интерактивная 3D-карта здания

● 3D-модель всех 4 этажей 
● Клик на любую зону → информация + маршрут
● Построение маршрута между любыми двумя точками
● Поиск по названию: «кафе», «лекторий», «выставка»
● Афиша событий прямо внутри карты

```

### Что говорим
> Наше решение — веб-приложение с интерактивной 3D-картой здания.
> Оно работает прямо в браузере, без установки.
> Посетитель видит объёмную модель всех четырёх этажей, может кликнуть на любое пространство и сразу узнать, что там находится, когда следующее событие и как туда добраться.
> Есть возможность выстроить маршрут по некольким выбранным мероприятиям
> Есть система рекомендаций товаров из магазина на основе выбранных мероприятий
> Есть интеграция ИИ помощника который призван разгрузить работников ресепшена типичными вопросами
> Всё это — в стилистике конструктивизма, потому что дизайн навигатора должен быть частью пространства, а не чужеродным элементом.

## Слайд 6 — Техническая реализация

### Что на слайде
```
Стек

Backend      Java 17 + Spring Boot 3 
База данных  H2 in-memory 
Frontend     Vanilla JS + Three.js
Маршруты     Алгоритм Дейкстры на графе зон
API-docs     Swagger UI / OpenAPI

```

### Что говорим
> Технически: бэкенд на Java / Spring Boot с REST API, фронтенд — чистый JS
> без фреймворков плюс Three.js для 3D.
>
> Ключевое архитектурное решение: зоны здания описываются не прямоугольниками,
> а секторами кольца — угол начала, угол конца, внутренний и внешний радиус.
> Это следует из формы здания — оно буквально цилиндрическое.
>
> Маршрутизация: при старте приложения строится граф — вершины это зоны,
> рёбра это переходы между соседними зонами и между этажами через лестницы и лифты.
> По этому графу запускается Дейкстра и находит кратчайший путь.
>
> Почему чистый JS без React или Vue? Потому что это требование кейса —
> приложение должно легко встраиваться в WordPress-сайт Центра «Зотов».
> Никаких сложных зависимостей, один скрипт — и всё работает.

## Слайд 8 — Перспективы развития

### Что на слайде
```
Три сценария использования уже сейчас:

[Сайт WordPress]          [Телефон]            [Киоск на входе]
iframe на странице    →   PWA, без магазина  →  Chrome fullscreen
centrezotov.ru            приложений             на ресепшн

Три шага к продакшну:

1. Сейчас (хакатон)
   Парсинг расписания с centrezotov.ru → H2

2. Ближайший следующий шаг
   ELMA365 API (база мероприятий Зотова) →
   события обновляются автоматически в реальном времени

3. Полная интеграция
   WordPress REST API + ELMA365 + PostgreSQL =
   единый источник данных для всех каналов

Дополнительно: AR-навигация, голосовой поиск,
интеграция с билетной системой, офлайн-режим внутри здания
```

### Что говорим
> Мы проектировали не просто хакатон-демо, а масштабируемую систему.
>
> Три сценария уже работают без изменений в коде:
> тот же URL встраивается в WordPress, открывается на телефоне как приложение
> и запускается в режиме киоска на экране при входе.
>
> По данным: сейчас используем парсер сайта centrezotov.ru.
> Как только Центр откроет доступ к ELMA365 — своей системе управления событиями —
> мы переключаемся на прямое API за полчаса. Архитектура уже готова,
> нужно только добавить ключ и включить одну настройку.
>
> В перспективе: дополненная реальность — навигация через камеру телефона,
> голосовой поиск, интеграция с покупкой билетов.
> Но самое главное уже работает.
