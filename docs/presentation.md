### Что на слайде
```
Зотов.Навигатор — интерактивная 3D-карта здания

● 3D-модель всех 5 этажей в браузере (Three.js)

● Афиша событий прямо внутри карты
● 5 режимов под разные сценарии использования

Режимы:
  Я впервые | На мероприятие | Всё посмотреть | С детьми | План дня
```

Скриншот или демо-гиф приложения.

### Что говорим
> Наше решение — веб-приложение с интерактивной 3D-картой здания.
> Оно работает прямо в браузере, без установки.
>
> Посетитель видит объёмную модель всех пяти этажей, может кликнуть на любое
> пространство и сразу узнать, что там находится, когда следующее событие
> и как туда добраться.
>
> Мы реализовали пять режимов — каждый режим адаптирует интерфейс под конкретный сценарий.
> «Я впервые» показывает только ключевые точки: вход, гардероб, касса, туалеты.
> «На мероприятие» сразу ведёт к афише и строит маршрут.
> «Plan дня» позволяет выбрать несколько событий и получить оптимальный обходной маршрут.
>
> Всё это — в стилистике конструктивизма: минимализм, геометрия, красный акцент.
> Потому что дизайн навигатора должен быть частью пространства, а не чужеродным элементом.

## Слайд 6 — Техническая реализация

### Что на слайде
```
Стек

Backend      Java 17 + Spring Boot 3  →  REST API
База данных  H2 in-memory (→ PostgreSQL одной строкой)
Frontend     Vanilla JS + Three.js    →  3D в браузере
Маршруты     Алгоритм Дейкстры на графе зон
API-docs     Swagger UI / OpenAPI

Как здание попало в 3D?
Зоны описаны секторами кольца (угол + радиус) —
потому что здание буквально круглое.

Как работает маршрут?
Граф зон → Dijkstra → пошаговые инструкции + анимация пути
```

Схема архитектуры (из `docs/zotov-navigator-spec.md`).

### Что говорим
> Технически: бэкенд на Java / Spring Boot с REST API, фронтенд — чистый JS
> без фреймворков плюс Three.js для 3D.
>
> Ключевое архитектурное решение: зоны здания описываются не прямоугольниками,
> а секторами кольца — угол начала, угол конца, внутренний и внешний радиус.
> Это следует из формы здания — оно буквально цилиндрическое.
>
> Маршрутизация: при старте приложения строится граф — вершины это зоны,
> рёбра это переходы между соседними зонами и между этажами через лестницы и лифты.
> По этому графу запускается Дейкстра и находит кратчайший путь.
>
> Почему чистый JS без React или Vue? Потому что это требование кейса —
> приложение должно легко встраиваться в WordPress-сайт Центра «Зотов».
> Никаких сложных зависимостей, один скрипт — и всё работает.

## Шпаргалка: возможные вопросы жюри

**«Почему не мобильное приложение?»**
> Веб-приложение работает на любом устройстве без установки, встраивается в сайт
> и запускается на киоске. PWA даёт те же возможности, что нативное приложение —
> иконка на экране, работа без интернета внутри здания.

**«Почему H2, а не реальная база?»**
> H2 — это выбор для хакатона: нулевая конфигурация, запускается мгновенно.
> Переключение на PostgreSQL — одна строка в application.yml. Данные,
> модель и все запросы остаются без изменений.

**«Как получаете данные о событиях?»**
> Сейчас парсим сайт centrezotov.ru раз в час. Центр ведёт мероприятия
> в ELMA365 — мы уже написали интерфейс для прямой интеграции,
> нужен только API-ключ от технической команды.

**«Почему не React/Vue?»**
> Требование кейса — возможность встраивания в WordPress.
> Чистый JS и Three.js не создают конфликтов с любой CMS.
> Размер бандла меньше, скорость загрузки выше.

**«Маршрутизация — как работает?»**
> При старте строится граф: вершины — зоны, рёбра — соседние секторы и лестницы/лифты.
> Вес ребра — расстояние в метрах между центрами зон.
> Поиск пути — Dijkstra. Для нескольких точек — жадный алгоритм ближайшего соседа.
