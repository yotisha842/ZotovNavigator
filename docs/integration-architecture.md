# Зотов.Навигатор — Архитектура интеграции

## Как это работает

Зотов.Навигатор — **самостоятельный веб-сервис** (Spring Boot), который живёт на отдельном хосте и не зависит от WordPress или любой другой платформы. Это даёт максимальную гибкость: одно приложение — три сценария использования.

---

## Три сценария использования

### 1. Встраивание в сайт Центра «Зотов» (WordPress)

Сайт centrezotov.ru работает на WordPress. Навигатор встраивается через стандартный iframe — не требует плагинов и не ломает структуру сайта.

```html
<!-- Вставить на нужной странице WordPress -->
<iframe
  src="https://navigator.centrezotov.ru"
  width="100%"
  height="700px"
  frameborder="0"
  allow="fullscreen"
></iframe>
```

Что нужно со стороны сервера навигатора — один заголовок в конфиге Spring Boot:

```yaml
# application.yml
server:
  headers:
    content-security-policy: "frame-ancestors https://centrezotov.ru"
```

Опционально можно оформить как WordPress shortcode `[zotov_navigator]` — это небольшой PHP-сниппет, который вставляет iframe автоматически везде, где используется шорткод.

---

### 2. Мобильное веб-приложение (PWA)

Посетитель открывает `navigator.centrezotov.ru` на телефоне. Браузер предлагает «Добавить на главный экран» — приложение устанавливается как нативное: своя иконка, работает без адресной строки, кэширует карту для работы без интернета внутри здания.

Для этого нужно добавить в проект два файла:

- **`manifest.json`** — название, иконка, цвета, режим отображения (`standalone`)
- **`service-worker.js`** — кэширование статики (Three.js сцена, CSS, JS)

Это около 40 строк кода, реализуется за полчаса.

---

### 3. Интерактивный киоск на входе

На ресепшн стоит планшет или моноблок. В браузере Chrome открыт навигатор в режиме киоска — без адресной строки, на весь экран, не закрывается случайно.

Запуск:
```bash
chrome.exe --kiosk --app=https://navigator.centrezotov.ru
```

Никаких изменений в приложении не требуется. Тот же URL, та же версия.

## Данные о мероприятиях — три стадии

### Стадия 1 (сейчас, хакатон)

Данные о событиях парсятся с официального сайта `centrezotov.ru` — расписание, названия, описания, постеры. Парсер запускается по расписанию раз в час и обновляет локальную базу H2.

```
centrezotov.ru ──(jsoup scraper)──→ EventSyncService ──→ H2 in-memory
                                         ↑
                               @Scheduled каждый час
```

Преимущество: работает прямо сейчас, без доступа к внутренним системам.

---

### Стадия 2 (после хакатона, приоритет)

**ELMA365** — low-code платформа, в которой Центр «Зотов» ведёт базу мероприятий. У неё есть стандартный REST API.

Как подключить:
1. Получить API-токен от технической команды Зотова
2. Написать `ElmaEventsClient` — реализацию того же `EventSyncService` интерфейса
3. Заменить парсер на клиент — остальной код не меняется

```
ELMA365 API ──(HTTP + Bearer token)──→ ElmaEventsClient ──→ PostgreSQL
   /api/v1/pub/app/{namespace}/list          ↑
                                   @Scheduled каждые 15 мин
```

Данные становятся актуальными в реальном времени, исчезает зависимость от HTML-структуры сайта.

---

### Стадия 3 (долгосрочно)

**WordPress REST API** — если Зотов захочет управлять контентом навигатора прямо из CMS:

```
WordPress (centrezotov.ru)
  /wp-json/wp/v2/events  ──→  наш EventSyncService
```

Также возможна двусторонняя интеграция: события из ELMA365 → WordPress → Навигатор, единый источник данных для всех каналов.

---

## Что предусмотрено в коде уже сейчас

| Элемент | Зачем |
|---|---|
| `EventSource` enum (`MANUAL`, `SCRAPER`, `ELMA365`) | Отслеживаем источник каждого события |
| `EventSyncService` интерфейс | Легко заменить парсер на ELMA365-клиент без переписывания |
| CORS открыт (`CorsConfig.java`) | iframe и мобильный браузер работают без ошибок |
| H2 → PostgreSQL переключение | Одна строка в `application.yml` при деплое |

## Для презентации — резюме

> **Зотов.Навигатор работает как самостоятельный сервис** — его не нужно встраивать внутрь WordPress, он живёт отдельно и подключается к любой платформе.
>
> **Сценарий 1 — сайт:** На сайте centrezotov.ru (WordPress) навигатор появляется через iframe — одна строка в коде страницы, никаких плагинов.
>
> **Сценарий 2 — телефон:** Посетитель открывает ссылку на телефоне, добавляет на главный экран — получает полноценное мобильное приложение без магазина приложений.
>
> **Сценарий 3 — киоск:** На входе в центр стоит экран с навигатором в полноэкранном режиме — тот же URL, ничего дополнительно настраивать не нужно.
>
> **Данные о мероприятиях:** Сейчас навигатор сам подтягивает расписание с официального сайта раз в час. Когда Центр «Зотов» даст доступ к ELMA365 — переключаемся на прямое API за 10 минут, данные становятся актуальными в реальном времени. Архитектура уже готова к этому переходу.
